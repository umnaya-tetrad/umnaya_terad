## Как пройти сценарии

После входа сверху открыта **«Панель UX-стенда»**. Быстрые кнопки **«История / Новая / Съемка / Разбор / Сводка»** ведут в настоящие экраны приложения. Панель можно свернуть кнопкой **«Скрыть панель»**, чтобы смотреть сам мобильный интерфейс.

В поле **«Сценарий»** выберите подготовленную проверку, затем **«Открыть экран»**. Поле **«Экран»** позволяет сразу открыть верное решение, первую ошибку, незавершенность, неоценимую задачу, просмотр перед завершением или сводку.

| Проверка | Что смотреть |
|---|---|
| `[UX 01]` Новая проверка вручную | Пустая тетрадь, фото, отправка, фон и обычный маршрут с начала |
| `[UX 02]` Ошибка, верно и незавершенное | Три независимых разбора; совместный комплект с продолжением на втором фото, номера фото и увеличение |
| `[UX 03]` Не хватает условия | Три оценимых задачи и одна `not_assessed`; пропуск только неоценимой задачи |
| `[UX 04]` Техническая ошибка и повтор | Первый Job безопасно завершается отказом; «Повторить проверку комплекта» создает успешный новый Job |
| `[UX 05]` Готовая сводка и обновление | Сохраненная сводка, изменение отзыва, устаревание и явное обновление |

**«Пройти с начала»** открывает чистую форму новой проверки. Для быстрого повторения есть **«Новая копия → обработка»**: она создает отдельную проверку `[UX RUN ...]`, добавляет фото и отправляет один комплект. Старые проверки и ручные изменения не удаляются. Для пустого сценария используется обычный набор демо-фото, пустой комплект не отправляется.

Чтобы не искать файлы, откройте съемку, разверните панель, выберите **«Демо-фото»** и **«Тетрадь для демо-фото»**, затем нажмите кнопку с нужным номером тетради. После перехода к следующей тетради панель подхватывает ее номер. Фото добавляются в черновик настоящими upload-запросами; отправку можно сделать обычной кнопкой учительского интерфейса.

Готовность намеренно задержана примерно на 4 секунды: можно увидеть очередь/обработку и продолжить работу с другой тетрадью. Зеленая и красная кнопки оценивают проверку системы, комментарий сохраняется обычным действием. Для окончательного завершения нужны все обычные отзывы и разрешенные пропуски — панель не обходит серверные блокеры.

Для устаревшей сводки выберите экран **«Изменить отзыв → устаревшая сводка»**. Он меняет один отзыв только в `[UX 05]` через штатный API. После этого обычная кнопка **«Обновить сводку»** строит новую учебную сводку. Сохраните несохраненный комментарий перед переходами панели.

## Что является моками

Настоящие: вход, API, PostgreSQL, приватные фото, версии, очередь и worker, сохранение отзывов, двухэтапное завершение, история и перезагрузка страницы. Подменена только граница провайдера: worker возвращает локальные валидные reports, сводка рассчитывается явным fixture transport.

Демо-фото и reports находятся в `dev/ux-workbench/`; страницы нарисованы программно без LLM и без школьных работ. Каталог доступен по `/ux-workbench/manifest.json`. Ответы фиксированы: **произвольная загруженная математика не распознается и не проверяется**. Это не тест качества ИИ, тарифа или скорости модели.

Панель включается только при одновременных `VITE_UX_WORKBENCH=true` и `VITE_PILOT_TRANSPORT=fixture`. В штатном `polza` приложение ее не загружает и игнорирует `ux_view`/`ux_task`/`ux_notebook`. Новых HTTP-endpoints, схем DTO, SQL-таблиц и промптов нет.

## Запуск оператором

Команды выполняются из корня этой ветки. Docker Desktop должен быть запущен. Для первого запуска подготовьте вне Git env-файл по `.env.example`, случайные секреты БД/cookie и аккаунты по [BOOTSTRAP](BOOTSTRAP.md). `POLZA_API_KEY` остается пустым; реальный ключ стенду не нужен. Учетная запись учителя должна существовать до HTTP seed. Ее можно создать штатной локальной CLI `pilot.operations.manage_accounts` по [RELEASE_RUNBOOK](RELEASE_RUNBOOK.md).

Две команды для уже подготовленного окружения (PowerShell):

```powershell
docker compose -p smartnote-ux-workbench --env-file C:/Users/User/.config/smartnote/ux-workbench.env -f compose.yaml -f compose.ux-workbench.yaml up -d --build --wait

$env:PILOT_TRANSPORT='fixture'; $env:POLZA_API_KEY=''; python scripts/pilot/seed_ux_workbench.py --credentials-file C:/Users/User/.config/smartnote/ux-workbench-account.json
```

На этой машине оператор использует последним дополнительный private override `C:/Users/User/.config/smartnote/ux-workbench.compose.yaml` для отдельных image tags и read-only source mounts. Этот файл не содержит продуктовых требований и не нужен для понимания сценариев. При его использовании добавьте `-f` с этим путем после tracked overlay.

`compose.ux-workbench.yaml` явно фиксирует `fixture`, пустой ключ и dev toolbar. Backend/worker/migrate/PostgreSQL находятся только во внутренней сети; только frontend подключен также к `ux_edge`, чтобы Docker Desktop публиковал локальный порт. Миграции и production endpoints не меняются. Учебный worker отказывается запускаться с `polza` или непустым ключом до обработки заданий.

Повторный HTTP seed находит пять точных названий и оставляет их текущие материалы, отзывы и сводки нетронутыми. Он не удаляет ручные проверки и `[UX RUN ...]`. Для повторения измененного сценария используйте новую копию в панели. Если первоначальный seed был прерван, уже созданная проверка также не перезаписывается; ее можно оставить для ручной работы.

Остановка только этого стенда с сохранением данных:

```powershell
docker compose -p smartnote-ux-workbench --env-file C:/Users/User/.config/smartnote/ux-workbench.env -f compose.yaml -f compose.ux-workbench.yaml stop
```

Локальный live-сервис остановлен отдельно, его данные сохранены. Этот стенд не переносит данные между проектами и не запускает платные запросы.

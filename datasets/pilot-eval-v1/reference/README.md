# Эталон для сверки после ответа модели

Это переносимая проекция ранее зафиксированного эталона, а не новая разметка или новая математическая проверка. [truth.json](truth.json) сохраняет все 178 появлений задач и исходные значения unit-полей; локальные пути изображений, записи генерации и промпты подготовки исключены. SHA256 исходного закрытого mapping записан в файле и manifest.

**Не отправляйте эти файлы, ожидаемые ответы, число задач, связи, вердикты и названия сценариев в LLM.** Для реального запроса нужны только фото из одного комплекта и рабочий промпт приложения.

Перед оценкой прочитайте [truth_errata.json](truth_errata.json). В B_N07, E_N07 и U_N07 подпункт h неоднозначен: на исходной рукописи у `100x²−160+63=0` не виден x после 160, а дальнейшие вычисления относятся к предполагаемому линейному члену. Прежний gold не исправлен задним числом. Только эти 3 появления исключены из основной математической оценки: 175 из 178 остаются в ней, все 178 остаются в составе входов, учете времени и стоимости. Это ранее обнаруженный дефект источника, без новой независимой учительской экспертизы.

Также сохранены прежние не исключающие замечания к записи B_N08__f и B_N06__b. Они не меняют ожидаемый математический вердикт/завершенность.

В K01–K04 исходный gold унаследовал `fragments` от родительских M01–M04, включая номер фото 2. Это исторические сведения о родительском комплекте, а не второе вложение одиночного control; собственный `photo_indices` равен `[1]`. Исходные значения сохранены для прослеживаемости. Действительный состав и порядок отправки задает только [manifest.json](../manifest.json): в каждом K-комплекте ровно одно фото.

Файлы содержат агентную самопроверку и статус прежнего источника; формулировки `review_status` не означают независимое подтверждение учителем. Правила из эталона не вводят обязательный `rule_id` в контракт приложения.

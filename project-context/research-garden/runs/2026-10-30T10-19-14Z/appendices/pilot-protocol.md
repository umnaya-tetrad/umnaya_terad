# Протокол сравнения: ручная проверка, чат и SmartNote

Это предлагаемый эксперимент. Ни один результат ниже не измерен. Пороговые значения — управленческие ориентиры для обсуждения с педагогами, а не научно установленные нормы.

## Этап 0: технический допуск

Выбрать две темы, например раскрытие скобок и линейные уравнения. Зафиксировать допустимые типы записи и условия задач. Подготовить 120 независимых решений: 60 верных и 60 с ошибкой, с разными почерками, допустимыми способами решения и качеством фото. Отдельно добавить 20 неподдерживаемых/нечитаемых случаев. Объём служит проверке осуществимости, не доказательству готовности всей школьной математики.

Два математика независимо размечают правильность, первый неверный переход, допустимые подсказки и читаемость. Разногласия разрешаются до оценки системы. Эталон не передаётся моделям. Разделять данные настройки и закрытую проверочную выборку, не использовать исправления из теста для повторной выдачи результата на том же тесте.

Технический допуск к живым подсказкам: отсутствие опасных/вводящих в заблуждение подсказок в педагогической экспертизе, приемлемые ошибки и отказы на закрытой выборке. При недопуске возможен только исследовательский просмотр взрослыми; не показывать автоматические заключения детям как достоверную проверку.

## Три условия

**A — ручная работа:** привычная проверка и составление краткой сводки ошибок.

**B — обычный чат:** доступная мультимодальная нейросеть, актуальное название/версия, настройки, тариф и дата фиксируются. Педагог получает хороший шаблон запроса и возможность привычных уточнений. Подготовка шаблона и перенос результатов в сводку включаются во время. Сравнивать с чатом без шаблона недостаточно.

**C — SmartNote:** тот же материал, условие задачи и критерии, фото, загрузка, обработка, просмотр, исправление и сводка. Предварительные выводы отделены от подтверждённых. Оценки для детей и журнала определяет педагог.

Для B и C одинаковые ограничения на выдачу готового ответа. Зафиксировать, какой компонент использует CAS, и стоимость всех вызовов. Если чат не принимает комплект нужного объёма, учитывать реальное разбиение и лимиты; не запрещать доступные ему функции искусственно.

## Запрос для чата — ученик

> На фото моя собственная попытка. Сначала проверь читаемость: не угадывай неразборчивые символы. Если условие нужно и отсутствует, попроси его. Найди первый неверный переход, если он есть. Укажи строку и объясни правило одним наводящим вопросом. Не давай исправленную цепочку и конечный ответ. Если проверить нельзя — назови причину. После моего исправления проверь его, сохраняя эти ограничения.

## Запрос для чата — учитель

> Проверь приложенные решения по условию и моим критериям. Для каждой работы верни номер, читаемость, предполагаемую правильность, первый ошибочный переход с указанием строки, правило и краткую допустимую подсказку. Отдельно укажи сомнения и неподдерживаемые случаи; не угадывай символы. Не выставляй итоговую оценку. Затем составь сводку повторяющихся ошибок по номерам работ. Критерии: [заполняет педагог].

## Дизайн полевого сравнения

Для проверки осуществимости — 3–6 педагогов, минимум три сопоставимых комплекта на педагога по 20–30 работ. Уравнять сложность; случайно распределить комплекты и порядок A/B/C. Один педагог не проверяет одну и ту же работу повторно другим способом: иначе работает память. Перекрёстное распределение между педагогами позволяет оценить те же материалы без повторного просмотра одним человеком. Общий эталон независим от проверяющих.

Засекать рабочее время педагога и отдельно календарное ожидание. Отмечать помощь исследователя: если команда загрузила фото, при расчёте эффекта добавить реальную стоимость этой операции. Сохранять периоды отказов, неудачные снимки и повторные запросы.

## Метрики и знаменатели

| Метрика | Расчёт |
|---|---|
| Полное время | Подготовка + съёмка + загрузка + просмотр + исправления + сводка, на комплект и на работу |
| Экономия | 1 − время C / время A; отдельно 1 − время C / время B |
| Precision ошибки | Верно отмеченные ошибочные работы / все отмеченные ошибочными |
| Recall ошибки | Верно отмеченные ошибочные работы / все действительно ошибочные; отказы не исключать |
| Ложная ошибка | Верные работы, ошибочно помеченные / все верные работы |
| Локализация | Правильно найденный первый неверный переход / все ошибочные работы; отдельно доля среди выданных локализаций |
| Покрытие | Работы с определённым выводом / все предъявленные; неподдерживаемую контрольную группу показывать отдельно |
| Отказы | Отказ / все предъявленные, с причинами: фото, задача, сомнение |
| Педагогическая пригодность | Допустимые подсказки / все выданные подсказки, оценка двух педагогов |
| Самостоятельное исправление | Исправленные без готового ответа / все доступные для исправления ошибки, отдельно по использовавшим помощь |
| Перенос | Результат новой сходной задачи без помощи через 2–7 дней |
| Стоимость полезного результата | Все переменные затраты, включая повторы / работы с принятым педагогом выводом |

Публиковать числа вместе с долями и неопределённостью, по педагогам и типам задач. Малый пилот не позволяет надёжно доказать обобщённый образовательный эффект.

## Решение после пилота

Предлагаемые ориентиры исходят из целей проекта: precision ≥85%, recall ≥80%, локализация ≥80% всех ошибочных работ; экономия полного времени ≥20% против A; самостоятельное исправление ≥50%. Дополнительно C должен давать ощутимое преимущество над B: ориентир ≥15% времени либо более полезный подтверждённый результат при сопоставимом времени. Покрытие и ложные ошибки рассматривать вместе с этими метриками, не компенсировать низкое покрытие красивой точностью.

Если преимущество есть только при съёмке силами команды, доработать сбор. Если чат не уступает — не масштабировать текущий сценарий; выбрать более узкую задачу либо интеграцию. Если педагогическая польза отсутствует — приостановить ученический режим. Критический неверный совет или нарушение согласованных условий данных — основание немедленной остановки живого этапа.

До детского этапа согласовать со школой/ответственным специалистом правовое основание, роли сторон, поставщиков обработки, доступ, сроки хранения и удаление. Начать с искусственных либо надлежащим образом обезличенных материалов; псевдоним вместо фамилии сам по себе не гарантирует обезличивание.

## Что собираем

Мобильное веб-приложение для учителей обычных школ: проверить настоящее ДЗ класса по алгебре 7–9, сверить разбор с тетрадью, отметить качество проверки ИИ и увидеть сводку математических ошибок. Вход по готовому личному аккаунту, без регистрации. Основной сценарий — телефон Android/iPhone; продолжение на другом устройстве поддерживается.

Поток: **Новая проверка с названием → условная тетрадь без ФИО → съемка задач с обработкой в фоне → готовые разборы в порядке готовности → согласие/ошибка ИИ → следующая тетрадь → обновляемая сводка.**

На фото может быть одна или несколько задач; решение может продолжаться на следующем фото. Независимые задачи и связи фото выделяет модель, R80. Граница совместного запроса определена R81: текущий draft-комплект отправляется отдельным действием. Съемка следующих комплектов и готовность ранее отправленных идут параллельно, R81. Работаем с интернетом, без офлайна и push. Отдельное фото условия отложено.

## Поддерживаемые сценарии страниц (R80)

| Вход | Результат |
|---|---|
| Одна задача целиком на одном фото | Один самостоятельный разбор |
| Несколько задач или самостоятельных подпунктов на одном фото | Отдельный разбор и отзыв для каждой независимой задачи |
| Одна задача начинается на первом фото и заканчивается на втором | Один разбор по обеим фотографиям; продолжение не новая задача |
| На первом фото целая задача и начало второй, на следующем продолжение | Два разбора; первая часть второй не считается незаконченной до просмотра всех фото |

Основной кандидат ядра — один запрос по совместному комплекту фото одной тетради. Модель сама выделяет независимые задачи и связывает продолжения. Локально проверены небольшие входы из 1–2 фото с агентной сверкой; это не гарантия качества любых реальных снимков или произвольных больших пачек. Продуктовая интеграция и развертывание еще не выполнены.

Граница комплекта и три действия отправки определены R81, Q47 закрыт; компактное отображение ключевых строк подтверждено R82, Q48 закрыт. Старое ограничение R07 «одна задача на фото» заменено R80. [Спецификация интеграции](AI_INTEGRATION.md), [AI-артефакты](ai/README.md).

## Действия текущего комплекта (R81, Q47 закрыт)

Учитель фотографирует страницу целиком. Не нужно заранее вручную выбирать каждую задачу. Текущий draft-комплект содержит упорядоченные фото одной тетради.

| Действие | Что происходит |
|---|---|
| «Добавить фото к комплекту» | Добавляет следующую фотографию в текущий draft, например продолжение решения на другом листе. До отправки все фотографии остаются в одном комплекте |
| «Отправить на проверку» | Фиксирует текущий комплект и отправляет все его фото одним LLM-запросом; учитель остается в этой тетради и может снимать следующий комплект |
| «Отправить на проверку и перейти к следующей тетради» | Отправляет текущий комплект и завершает ввод материалов текущей тетради, открывая следующую. Не ждет модели и не завершает всю проверку или расчет сводки |

Пустой draft ничего не отправляет; оба отправляющих действия недоступны до добавления фото. Сервер подтверждает прием только после надежного сохранения входа. До отправки фотографии хранятся в draft; отправленная версия неизменяема. Позднее можно вернуться к тетради и добавить новый комплект — действие перехода не является постоянной блокировкой тетради.

Результаты ранее отправленных комплектов показываются по готовности, пока учитель снимает следующие. Камера/съемка не ждут модели; появление результата не должно принудительно прерывать съемку. Комплекты обрабатываются в фоне независимо от вкладки и текущей тетради. Связанные страницы передаются вместе, продолжение не отправляется как самостоятельная новая задача.

[PlantUML-схема потока](ai/capture-flow.puml). R82 (Q48 закрыт): показываем до четырех ключевых распознанных строк, без полной транскрипции, и первый ошибочный шаг с правилом/пояснением/исправлением.

## Что зафиксировано

| Область | Решение |
|---|---|
| Проверка | До первой математической ошибки; шаг, тип, правило, объяснение и правильная запись этого шага. Незавершенность отдельно |
| Контроль учителя | Зеленое «✓ Согласен с проверкой», красное «Ошибка в проверке ИИ»; необязательный комментарий, без редактора вывода |
| Фото и оформление | Камера/галерея, предпросмотр/пересъемка, увеличение; без PDF, обрезки, ручного поворота и подсветки на фото. Клетчатый стиль и цвета product-kit |
| Сводка | Подтвержденные результаты; работы с ошибками/без, среднее по полностью подтвержденным непустым тетрадям, топ-3 математических правил; частичные/спорные отдельно |
| Изменения | Добавлять задачи/тетради позже; менять отзыв/комментарий; заменять фото с повтором и снятием прежнего согласия; удалять задачу/тетрадь/проверку с подтверждением, без корзины |
| Сохранение | Серверная обработка после закрытия; фото, разборы, отзывы и журналы сохраняются. Конца апробации и автоматического удаления пока нет |
| Ядро | Gemini через Polza; CAS развивается отдельно. Один автоповтор временного технического сбоя, затем ручное действие |
| Команда | Закрытый раздел просмотра проверок и материалов с аудитом. Подробные логи, без дашборда |
| Размещение/расходы | Существующие сервер и домен, пилот заменяет лендинг. Ориентир 400 ₽/месяц; учительских квот нет, серверный контроль средств и пополнение командой |
| Поддержка | Мессенджер, отвечает команда по возможности в течение дня, без фиксированных часов. Приостановка вручную, не по числу красных отметок |

Рабочий объем — несколько одновременно работающих учителей, до 30 тетрадей по 3–5 задач в проверке. Это ориентир нагрузки, не пользовательский лимит. Цель ожидания одной задачи — 5–15 секунд, еще без измеренного подтверждения.

Пятничная демо-встреча подтверждена; полноценная апробация начинается с понедельника. По календарю обсуждения это 20 и 23 ноября 2026 года; числовые даты раскрыты из относительных слов пользователя. Для первого успеха достаточно самостоятельной проверки ДЗ и полезного разбора, без доказанной экономии времени. Письменный итог нужен; его формат пока не выбран и функций приложения не блокирует.

## Как использовать спецификацию

Сначала прочитать PRODUCT, затем TEACHER_FLOW, SUMMARY_METRICS и технический план. Подтвержденные требования этой папки определяют текущий пилот; старые макеты и корневые планы дают контекст, но не меняют согласованный поток. Технические решения разработчика явно отделены от решений владельца.

[Карта источников](../docs/KNOWLEDGE_MAP.md) объясняет роль трех исходных систем. [Статический аудит](../docs/INTEGRATION_AUDIT.md) описывает найденный код. Изменения этой консолидации ограничены документацией. Код исходных приложений не менялся; развертывание и школьная апробация не выполнялись. Отдельный локальный AI-эксперимент описан в AI_INTEGRATION и не является приемкой приложения.

# Проверка общего пакета v1

19.11.2026. Общий пакет подготовлен параллельно архитектором API, архитектором модулей и UX-редактором; аналитический контракт и общую проверку собрал координатор. Личные характеристики и обстоятельства участников не являются входом этого документа.

## Фактические проверки

`python check_shared.py` из shared выполняет проверки frozen-артефактов, коротких текстов, формальной структуры OpenAPI и fixtures, аналитики и негативных контрактных тестов. Проверяются именно файлы, а не наличие заголовков в MD. Это не тест реализованного приложения.

Окончательный запуск: **34 HTTP-операции, 44 HTTP fixtures, 25 lifecycle-снимков, четыре пары аналитики, 158 используемых строк UX, 73 офлайн-теста — PASS**. Проверены также drift генерации TypeScript/Python/OpenAPI/schema и валидный PNG fixture 64×64. Платных запросов, браузерных проверок приложения или развертывания при подготовке не было.

## Независимое ревью

Статус: **PASS как основы для трех подробных ТЗ**. Два независимых ревьюера проверили техническую полноту и сквозной мобильный сценарий; первый самостоятельно повторил общий gate. Исправлены все выявленные блокирующие расхождения. Редакционный остаток rename в таблице владельцев также удален. TASKS/ACCEPTANCE/HANDOFF трех направлений затем подготовлены и прошли [отдельное перекрестное ревью](../TASK_REVIEW.md).

Исправления по ревью: история всех поколений одного InputVersion через HistoryVersion.runs; совпадающий URL удаления draft-фото; retry того же snapshot только при свежем failed; refresh по серверному can_refresh с безопасной заменой неотправленного stale queued/blocked и запретом для running/unknown; сообщение пустой проверки перед финалом; нейтральные спорные разборы. Удалены неиспользуемые переименования, номер тетради назначает сервер. У teacher нет отдельного экрана истории запусков; для поддержки история доступна staff.

Поле/операция должны иметь потребителя в полном сценарии или в согласованной поддержке. Отдельно проверяются смешанный Report, перезапуск/дубли, версии/поздние ответы, удаление общего фото, двухэтапный финал, состояние аналитики после правок и отсутствие вечерней зависимости от проектирования ядра.

В последующей детализации согласованы LOCAL_ENV, режим fixture/polza с видимой учебной меткой, единая upload/worker граница8_000_000/36MP/min32 и отсутствие ранней зависимости от staff-модуля. Итоговый crossreview трех ТЗ учитывает эти уточнения; необоснованные rename/admin-поля не возвращались.

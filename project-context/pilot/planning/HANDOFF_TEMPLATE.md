# Шаблон состояния и передачи

Создать HANDOFF.md в папке соответствующего направления и обновлять при готовом результате или блокере. Синхронная встреча для чтения файла не требуется. Шаблон не является отчетом о выполненной работе.

```text
Направление:
Ветка и commit:
Версия общего контракта и ссылки на OpenAPI/схемы/fixtures:
Время обновления (с часовым поясом):

Готово:
- Пункт ТЗ / результат / как проверить.

Еще не готово:
- Пункт ТЗ / влияние / кто продолжает.

Запуск и подготовка данных:
- Команды, миграции, fixtures/создание тестовых аккаунтов.
- Имена нужных переменных без значений секретов.

Выполненные проверки:
- Команда / результат / версия кода.
- Отдельно: подставной transport и реальные запросы/расходы, если разрешены.

Блокеры:
- ID / серьезность / затронутый контракт или пункт ТЗ.
- Входные данные / команда воспроизведения.
- Фактический результат / ожидаемый результат.
- Следующий шаг / владелец исправления.

Доказательство совместимости ядра:
- API smoke завершения и аналитики / fixture / команда / результат / commit.

Передача интегратору:
- Какие коммиты включить, зависимости и порядок миграций.
- Известные конфликты, способы диагностики и восстановления.
- Какие требования не подтверждены выполненной проверкой.
```

Не включать пароли, токены, реальные школьные материалы и личные характеристики участников. GitHub — основной канал передачи файлов/коммитов. Перед фиксацией финального результата интегратор проверяет наличие кодовых коммитов, а не только отметок «готово».

# Руководство по интерфейсу из ролика

## Назначение и версия

Экраны перенесены из демонстрационного видеопроекта «Умная тетрадь». Основа — AppScreen и финальный монтаж v6 длительностью 2:15. В комплект входят 26 состояний приложения и 2 состояния камеры. [HTML-каталог](../preview/index.html) предназначен для просмотра; [интерактивный прототип](../preview/app.html) — для прохождения действий.

Макеты показывают согласованный в октябре образ продукта. Новые планы команды зафиксированы в [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md). Если они расходятся с макетами, это повод уточнить следующий дизайн, а не объявить ноябрьскую функцию уже реализованной. Исходные формулы, счётчики и работы демонстрационные.

## Учительский сценарий

Учитель организует материалы по иерархии «класс → тема → домашняя работа с датой → комплект фотографий». Тема объединяет несколько домашних работ; создание темы и создание конкретной работы — разные действия.

| ID | Экран | Назначение и следующий шаг |
|---|---|---|
| Roles | Выбор роли | Вход в учительский или ученический сценарий |
| Teacher | Кабинет учителя | Классы, сводка, начало проверки, добавление класса |
| NewClass | Новый класс | Ввод названия; создание демонстрационного класса |
| Class | Темы класса | Выбор существующей темы или добавление новой |
| NewTopic | Новая тема | Ввод названия внутри выбранного класса |
| Topic | Домашние работы | Список работ с датами и создание очередной работы |
| Create | Новая домашняя работа | Название и дата; переход к добавлению комплекта |
| UploadEmpty | Комплект не выбран | Исходное состояние перед имитацией выбора фотографий |
| Upload | Комплект выбран | Нумерованные работы, начало предварительной проверки |
| Processing | Обработка комплекта | Иллюстрация процесса; в прототипе переход к отчёту по кнопке |
| Report | Отчёт | Сводка комплекта, очереди подтверждения и внимания, аналитика |
| Queue | Очередь подтверждения | Выбор отдельной работы с высокой уверенностью системы |
| Review | Работа целиком | Фото/разбор, подтверждение или отклонение результата |
| Confirmed | Подтверждение принято | Следующая работа либо возврат к отчёту |
| Attention | Требуют внимания | Нечитаемые, сомнительные и отклонённые преподавателем работы |
| Manual | Дополнительная проверка | Учитель просматривает работу и отмечает её просмотренной |
| Analytics | Частые ошибки | Сводка по типам ошибок; переход к связанным работам |
| ErrorWorks | Работы с выбранной ошибкой | Фильтр по типу ошибки и просмотр примеров |

**Разделение статусов.** Предварительное «без ошибок» и принятое педагогом заключение не равны. Нажатие «Подтвердить» добавляет номер работы в confirmed; «Отклонить» добавляет в rejected и направляет к дополнительному вниманию. Прототип обновляет очередь и счётчики принятых/отклонённых работ. Общие показатели «12 / 7 / 3 / 2» — фиксированная иллюстрация; это не вычисляемая аналитика реального комплекта.

Массовое подтверждение не предусмотрено. Номера заменяют персональные данные учащихся. Окончательная оценка остаётся у учителя. Экран Manual не моделирует полноценную систему выставления баллов или редактирования математических выводов.

Переход в аналитический раздел в v6: подтверждение работы → касание «Вернуться к отчёту» на 59,2 секунды → отчёт на 60-й секунде → касание «Частые ошибки» на 64,2 → аналитика на 66-й секунде. Это устраняет переход без показанного действия.

## Ученический сценарий

Ученик должен принести собственную попытку решения, сфотографировать её, проверить читаемость и только затем запустить проверку. После подсказки он исправляет тетрадь и снимает её повторно. Внутри приложения исправление шагов не производится.

| ID | Экран | Продуктовая роль |
|---|---|---|
| Student | Кабинет ученика | Основное действие и короткая инструкция |
| Photo | Добавление фотографии | Старый вариант макета выбора изображения; сохранён для сравнения |
| CameraCapture | Камера первого снимка | Рамка, расположение решения, кнопка затвора |
| PhotoPreview | Всё хорошо видно? | Подтверждение читаемости, проверка или пересъёмка |
| Scan | Анализ решения | Иллюстрация распознавания и проверки |
| Error | Ошибочный шаг и правило | Обратная связь без выдачи готового ответа |
| Retry | Исправление в тетради | Напоминание сделать новую фотографию |
| CameraRetry | Камера повторного снимка | Исправленный пример в рамке; новый снимок |
| RetryPreview | Просмотр нового снимка | Повторная проверка или пересъёмка |
| Success | Теперь верно | Сообщение об успехе и проверка другого решения |

В интерактивном прототипе переход к Photo открывает CameraCapture, переход к Retry — CameraRetry. Сами состояния Photo и Retry доступны напрямую через каталог: так сохранены исходные макеты и показанная в ролике камера. Видеоряд отдельно показывает этап напоминания Retry перед камерой повторного снимка. Это задокументированное отличие оболочки от монтажа.

В исходном примере `3(x + 2) = 15` ошибочная строка — `3x + 2 = 15`. Подсказка объясняет умножение на каждое слагаемое; она не выдаёт школьнику готовую исправленную цепочку. Повторный снимок содержит `3x + 6 = 15`, `3x = 9`, `x = 3`. Фотографии заменены типографическими иллюстрациями: в камере используется рукописный системный шрифт, на просмотре — исходное оформление макета. Визуально это не одна реальная фотография; реальные фотографии должны заменить обе заглушки согласованно.

Ни одного обращения к ИИ, устройству камеры или пользовательским файлам не происходит. Переходы Error и Success заданы сценарием; качество распознавания по ним оценивать нельзя.

## Стиль и композиция

Базовая область приложения — 430×932. Цвета: бумага `#ebe4d4`, кремовый `#f8f1dc`, чернила `#111713`, синий `#2456b3`, красный `#ef4147`, жёлтый `#f3cd45`. Используются клетка внутри приложения, плотные чёрные границы, смещённые тени, крупные заголовки и цветовые акценты для действий и состояний. Иконки — lucide-react; знак тетради — локальный SVG NotebookMark.

В ролике внешнее поле белое. Корпус условного телефона имеет камеру-капсулу, статусную строку и нижний индикатор. Общий план сменяется приближением нужного участка: zoom in 1,6 секунды, zoom out 0,8. Касание обозначается кругом и пульсацией. Некоторые служебные подписи и кнопки возврата скрыты только в видеокомпозиции, чтобы крупный план оставался читаемым. В полноразмерных макетах они доступны.

Гарнитуры системные: Aptos / Segoe UI / Arial; иллюстрация записи в камере — Segoe Print / Georgia. Вид на другой ОС может немного различаться. Комплект не включает сторонние шрифтовые файлы и не делает сетевые запросы за ними.

## Как использовать материалы

- Исследователю: открывать макеты как иллюстрацию сценариев, не как перечень подтверждённых функций. Контекст ноября читать первым.
- Дизайнеру: менять общие стили в screens.css; внешний корпус и монтаж — отдельно в action.css. После правок пересобирать HTML.
- Разработчику: использовать AppScreen как визуальный слой. Перед подключением сервера вынести модель работ и статусов из демосостояния и заменить предопределённые переходы реальной обработкой.
- Команде перед показом: проверить актуальность обещаний, совпадение снимков и формул, статус каждой функции и реальные результаты испытаний.

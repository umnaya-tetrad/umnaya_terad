# Публичный лендинг и модуль разбора решения

Публичный путь — [http://localhost:5173](http://localhost:5173). Это ретро-лендинг «Умной тетради» с рабочим сценарием: пользователь выбирает фотографию решения, фронтенд отправляет её на `POST /api/analyze`, а валидный ответ отображается под панелью загрузки с формулами, шагами и первой найденной ошибкой.

В пилоте принимаются JPG, PNG и WebP до 8 МБ. Фото используется только в памяти на время запроса и не сохраняется проектом. Сервер по-прежнему валидирует файл и JSON-контракт до того, как данные попадут в интерфейс.

Дневной бесплатный лимит не показан заранее и не блокирует выбор фото. Только после нажатия «Проверить решение», если сервер вернул исчерпание лимита, открывается модальное окно: его можно закрыть кнопкой «Отмена» или перейти на публичную страницу тестовых тарифов [http://localhost:5173/pricing](http://localhost:5173/pricing). Оплата в этом MVP не подключена.

## Запуск в контейнере

```bash
docker compose up --build
```

После запуска открыть [http://localhost:5173](http://localhost:5173).

Для сценария с реальным фото сначала скопируйте `.env.example` в `.env`, добавьте `POLZA_API_KEY`, затем выполните `docker compose up --build`. Подробности, ограничения и карта кода — в [сценарии интеграции](backend-integration.md).

Для остановки контейнера:

```bash
docker compose down
```

## Внутренние инструменты

По умолчанию служебный интерфейс выключен: любой путь, включая `/internal`, открывает публичную главную. Для локальной работы с моками, импортом JSON и бенчмарком задайте в `.env`:

```env
VITE_ENABLE_INTERNAL_TOOLS=true
```

Затем обязательно перезапустите Vite или `docker compose`, поскольку это compile-time переменная Vite. После этого внутренний экран доступен по [http://localhost:5173/internal](http://localhost:5173/internal). Значение флага не является секретом; `POLZA_API_KEY` остаётся единственным секретом интеграции.

На внутреннем экране доступны следующие сценарии:

- **Найдена ошибка** — две зелёные карточки и первая красная карточка с объяснением. В моке специально присутствует шаг после ошибки, но UI его скрывает.
- **Всё верно** — все распознанные шаги отображаются зелёными.
- **Нужно уточнение** — статус `insufficient_context` с понятной просьбой прислать полный контекст.

Во вкладке **«Загрузить JSON»** можно вставить ответ LLM как обычный текст JSON и нажать **«Показать разбор»**. Файл `.json` остаётся дополнительным способом ввода. Данные проверяются и отображаются только в браузере: запросы на сервер и загрузка куда-либо не выполняются.

Для первой проверки можно загрузить [`examples/analysis-response-example.json`](../examples/analysis-response-example.json).

Формулы рендерятся KaTeX. Типы ответа находятся в [`src/types/analysis.ts`](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/src/types/analysis.ts) и повторяют ключевые поля контракта LLM.

# Сценарий «фото → Polza AI → разбор»

Этот документ описывает первый рабочий путь пилота. Фото не записывается в БД, в каталог проекта или объектное хранилище: сервер читает ограниченный файл в память, проверяет его, кодирует в Base64 для одного вызова Polza AI и после ответа освобождает байты.

## Как это работает

1. Посетитель выбирает JPG, PNG или WebP до 8 МБ в блоке проверки на публичной главной.
2. Браузер отправляет файл `multipart/form-data` на `POST /api/analyze` через прокси Vite.
3. FastAPI проверяет заявленный MIME-тип, реальное содержимое изображения, размер и разрешение в памяти.
4. Адаптер Polza AI отправляет `POST /chat/completions` с фотографией как `data:image/...;base64,...`, высокой детализацией и `response_format` с JSON Schema из `app/schemas.py`.
5. Сервер повторно валидирует JSON Pydantic-моделью. В частности, он отклоняет дополнительные поля, шаги после первой ошибки и несогласованный статус.
6. Фронтенд получает только валидный контракт версии `1.0` и показывает его существующим компонентом разбора.

Локальное Base64 подходит для пилота: Polza AI описывает именно этот способ для локальных файлов. В дальнейшем при более крупных изображениях понадобится отдельное решение для сжатия на клиенте или временного хранилища с политикой удаления, но не постоянное хранение оригиналов.

## Настройка ключа

1. Создайте ключ в кабинете Polza AI.
2. Скопируйте шаблон:

   ```bash
   cp .env.example .env
   ```

3. Впишите ключ в `.env`:

   ```dotenv
   POLZA_API_KEY=ваш_ключ_из_polza
   ```

`.env` игнорируется Git. Не добавляйте ключ в исходный код, документацию, скриншоты или логи. Ключ и базовый URL настраиваются в `.env`; выбор модели намеренно хранится в [`app/model_catalog.py`](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/app/model_catalog.py), чтобы он был воспроизводимым и не зависел от локального окружения. Для текущего MVP зафиксирована `google/gemini-3.7-flash`; она должна принимать изображение и возвращать structured output.

## Запуск

```bash
docker compose up --build
```

- Интерфейс: `http://localhost:5173`
- Проверка состояния API: `http://localhost:8000/api/health`

После запуска откройте главную, выберите снимок с условием и шагами в блоке «живой сценарий», затем нажмите «Проверить решение». Если ключ не задан, интерфейс честно сообщит об этом. Мок-режимы, ручная вставка JSON и бенчмарк скрыты на `/internal` и требуют `VITE_ENABLE_INTERNAL_TOOLS=true`; подробности — в [описании фронтенда](frontend-demo.md).

Для реальной регрессии на пяти синтетических алгебраических фото используйте `docker compose exec backend python run_e2e_examples.py`. Набор и ожидаемые результаты находятся в [`inputExamples/README.md`](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/inputExamples/README.md).

## Бесплатный дневной лимит

Публичный MVP даёт три успешных распознавания в календарный день на одного анонимного посетителя. Сервер при первом API-запросе выдаёт непрозрачный `HttpOnly`, `SameSite=Lax` cookie. В PostgreSQL сохраняется только HMAC-SHA-256 этого значения, а не cookie, IP-адрес, фото или ответ модели.

`GET /api/quota` остаётся техническим endpoint для будущих экранов, но публичный лендинг заранее остаток не показывает и не блокирует выбор фото. При `429` после нажатия «Проверить решение» интерфейс показывает модальное объяснение с переходом на `/pricing` или «Отмена». Перед вызовом Polza API сервер создаёт короткую резервную запись: она защищает от параллельных вкладок, но ещё не является списанной попыткой. Резервирование становится использованным только если Polza вернула ответ, прошедший JSON-контракт, со статусом `ok`. Нечёткое фото, не математическая задача, ошибка сети/провайдера или невалидный JSON освобождают слот. Резервации автоматически истекают через четыре минуты, например после обрыва процесса.

Это устойчиво к F5, повторному открытию вкладки и очистке React-state. Как и любой анонимный cookie-лимит, он не может полностью остановить намеренный обход через очистку cookie, другой браузер или приватный режим; для более жёсткой защиты потребуются авторизация/телефон и антифрод на уровне edge/WAF. В production задайте уникальные `POSTGRES_PASSWORD` и `VISITOR_COOKIE_SECRET`, включите `VISITOR_COOKIE_SECURE=true` под HTTPS.
| `app/image_validation.py` | Валидация фото в памяти, без записи на диск |
| `app/prompts.py` | Инструкция модели: первый ошибочный шаг и русские объяснения |
| `app/polza_client.py` | OpenAI-совместимый запрос к Polza AI, Base64 и server-side валидация ответа |
| `app/schemas.py` | Pydantic-схема и инварианты контракта `1.0` |
| `app/main.py` | Тонкий HTTP-маршрут, коды ошибок и CORS |

Сервер не записывает в логи изображение, ключ, полный промпт или сырой ответ провайдера. Ошибка провайдера возвращается пользователю как нейтральное сообщение без технических деталей.

Для внешнего соединения задан отдельный `POLZA_CONNECT_TIMEOUT_SECONDS=10`: при недоступности сети пользователь не ждёт полный таймаут ответа модели.

Клиент Polza AI создаётся с `trust_env=False`: HTTP(S)-прокси из окружения контейнера или ОС для этого исходящего вызова не используются.

Продуктовый комплект содержит 28 экспортированных состояний (26 приложения, 2 камеры), интерактивный React-прототип, исходники ролика и MP4 135 секунд. ## 3. Фактический путь обработки в лендинге

1. [PhotoAnalysis.tsx](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/src/components/PhotoAnalysis.tsx) принимает один файл, делает локальный предпросмотр и отправляет `multipart/form-data` на `/api/analyze`.
2. [main.py](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/app/main.py) использует анонимный cookie, валидирует файл и резервирует слот дневного лимита.
3. [model_catalog.py](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/app/model_catalog.py) фиксирует `google/gemini-3.7-flash`, `json_object`, `temperature=0`, максимум 4000 completion tokens. Это идентификатор из кода; актуальная доступность поставщика не проверялась.
4. [prompts.py](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/app/prompts.py) выбирает `linkage_v2`. Экспериментальный `full_solution_audit_v4_unverified` присутствует, но не является текущим и помечен непроверенным.
5. [polza_client.py](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/app/polza_client.py) отправляет Base64 в Polza, добавляет описание схемы к промпту для `json_object`, затем валидирует результат Pydantic. Не следует описывать текущий вызов как принудительный `json_schema` на стороне провайдера.
6. При валидном `status=ok` резерв списывается; отказ модели или сбой освобождает слот. В PostgreSQL найдены только таблицы `daily_quota_usage` и `daily_quota_reservations`.
7. [AnalysisResult.tsx](https://github.com/svn-re7/SmartNoteLanding/blob/b8423b01a5eb56601539e83d14c382d23eea1a61/src/components/AnalysisResult.tsx) показывает шаги, объяснение и при наличии `corrected_latex` – блок «Правильный вариант».

По Compose лимит – 3 успешных разбора в день, часовой пояс `Asia/Yekaterinburg`, срок резерва 240 секунд. Реальный `/api/analyze` требует настроенной БД; успешный `/api/health` сам по себе не проверяет БД, ключ и модель. Фото серверным кодом намеренно не сохраняются. Учительский доступ и хранение результатов не следуют из наличия PostgreSQL.

## 4. Расхождения, которые нельзя переносить незаметно

| ID | Источники расходятся | Как учитывать |
|---|---|---|
| C01 | Landing-контракт обещает разные разделы математики; текущий контекст ограничивает продукт алгеброй 7–9 | Актуальный продуктовый охват брать из корня. Определить проверенный список тем; широкий промпт не считать доказательством поддержки |
| C02 | Landing-промпт/схема/UI допускают готовый исправленный шаг; школьный ученический сценарий требует правило без исправления | До ученического этапа изменить выдачу вместе с контрактом и тестами. Для учительского просмотра состав данных определить отдельно |
| C03 | `architecture.md` описывает `users`, `attempts`, `analysis_results`, `events`, `consents`, наблюдаемость; в коде найдена только БД лимита | Документ описывает целевую архитектуру. Не объявлять историю, согласия, аналитику и кабинеты реализованными |
| C04 | Интеграционная документация говорит о JSON Schema/structured output; выбранная модель в коде использует `json_object` | Фактический режим брать из каталога и адаптера; серверная Pydantic-валидация обязательна в обоих случаях |
| C05 | Педагогу нужно видеть исходное фото и возвращаться к проверке; исторический серверный дизайн запрещает хранение оригиналов | Реализовать обязательное серверное сохранение фото/разборов/отзывов и возврат по R26/R56: после апробации сохраняем, автоматического удаления нет. Показ фото только из памяти браузера требование не выполняет |
| C06 | Макеты показывают загруженный комплект и аналитику; часть чисел фиксирована | Рабочую сводку строить из реальных данных; демонстрационный режим обозначать отдельно |
| C07 | Лендинг содержит цены, лимит и переход на тарифы; это исторический тарифный сценарий | По R60 убрать квоты 3/20, счетчики остатка, тарифные переходы и соответствующие серверные ограничения из пилотного пути. Финансовый контроль средств остается на сервере, пополнение выполняет команда |
| C08 | Корневой контекст передает сообщение о первичных кабинетах; в этом checkout найдена анонимная идентичность | Не отрицать существование другого задела команды, но в данном коде аккаунты не подтверждены. Уточнить расположение другой реализации |
| C09 | Часть README/AGENTS benchmark говорит о 10 фото, поздние документы и JPG в папке – о 11 | Для состава брать файлы и manifest конкретного набора. Не менять знаменатель исторического запуска задним числом |
| C10 | В старом школьном отчете жесткое число контактов и шире ученический формат; ноябрьские решения уточнили маршрут | Использовать корневой школьный процесс, гибкое число контактов и первый учительский фокус |

Отдельный технический нюанс C05: `UploadFile` использует spooled-файл. В `main.py` поднят `spool_max_size` до лимита фото, однако это само по себе не доказывает отсутствие записи на диск для произвольной слишком большой загрузки до ее отклонения. Это отмечено и в архитектурной документации. Перед обещанием строгой обработки только в памяти нужна проверка границы запроса/прокси; текущий осмотр не является аудитом приватности.

## 6. Проверки и воспроизводимость

В `product-kit/docs/STATUS.md` описаны успешные прежние сборки, smoke-рендеры и отдельные браузерные переходы. Это история упаковки комплекта. В лендинге найдены frontend- и backend-тесты, benchmark-скрипты и сохраненные сводки. В этой задаче они прочитаны, но не запускались.

Команды для будущей проверки после изменений:

| Где выполнять | Проверка |
|---|---|
| `SmartNoteLanding` после `npm ci` | `npm test`, `npm run build` |
| `SmartNoteLanding/app` в Python-окружении с `requirements.txt` | `python -m pytest` |
| `SmartNoteLanding` при доступном Docker | `docker compose up --build`; затем проверить API, интерфейс и реальные состояния |
| `product-kit` после `npm ci` | Полный набор из его `AGENTS.md`: lint, build, build:prototype, build:offline, render:smoke, still:smoke; `node scripts/verify-kit.mjs` |

`run_e2e_examples.py` и benchmark обращаются к настоящему провайдеру и расходуют API-бюджет; их не путать с автономными unit-тестами. Реальная проверка учительского комплекта должна дополнительно охватывать частичный сбой, сохранение правок, повторное открытие и правильную сводку.

В исходном `STATUS.md` комплекта также сохранен прежний отчет `npm audit`: 24 уязвимости. Новый аудит зависимостей здесь не выполнялся; обновление пакетов не было частью объединения документации.

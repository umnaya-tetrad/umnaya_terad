# Работа с документацией SmartNote

Общие правила и назначение трех skills — в [корневом AGENTS.md](../AGENTS.md). Для входа в контекст используй smartnote-pilot, после изменений smartnote-doc-sync, перед push/merge smartnote-preflight. Пошаговая карта обновлений — [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md).

Текущая спецификация — [pilot/README.md](pilot/README.md); статус реализации — [CURRENT_STATE.md](CURRENT_STATE.md); решения владельца — [pilot/DECISIONS.md](pilot/DECISIONS.md). Подтвержденные требования пилота приоритетнее ранней концепции, исследований и снимков source-документов.

Не переопределяй R-решения технической догадкой. При настоящем новом ответе добавь следующее свободное R-ID и обнови затронутые спецификации; при реализации согласованного поведения обновляй техническое описание и фактический статус без выдуманного нового решения владельца.

Для существенной функции сохраняй связь: зачем → участник/вход → действие → результат → ограничения → источник/задел → проверка. Отличай проверку до первой ошибки, завершенность решения и согласие с системой. Фото, задача, тетрадь и проверка — разные единицы.

Архивы history, research-garden и references не являются текущими требованиями. Снимки исходных AGENTS названы AGENTS.source.md; не распространяй их правила на эту папку. Нужные исходники и закрепленные ссылки — [SOURCES.md](SOURCES.md).

Не клади в документацию секреты, реальные работы учеников и сырые production-ответы. Никакая запись о плане/спецификации не означает успешную реализацию, развертывание или согласие школы.

После изменений запусти из корня python scripts/check_context.py. При изменении исторических путей сохрани происхождение и переносимость ссылок; исходные архивные выводы не переписывай как современные факты.

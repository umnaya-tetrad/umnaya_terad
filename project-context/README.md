# Документация и контекст SmartNote

Самодостаточная база знаний для коллег и нового агента. Каноническая текущая спецификация — [pilot/README.md](pilot/README.md). Вход для агента — [корневой AGENTS.md](../AGENTS.md) и skill smartnote-pilot; текущая стадия — [CURRENT_STATE.md](CURRENT_STATE.md).

| Слой | Содержание |
|---|---|
| [pilot/](pilot/README.md) | Согласованные требования R01–R79, пользовательский поток, формулы, технический план, этапы и приемка |
| [PROJECT_CONTEXT.md](PROJECT_CONTEXT.md), [PRODUCT_DESCRIPTION.md](PRODUCT_DESCRIPTION.md), [SCHOOL_PROCESS.md](SCHOOL_PROCESS.md) | Общая концепция, контекст команды и школьный маршрут; раздел 1 контекста актуализирован |
| [docs/](docs/KNOWLEDGE_MAP.md) | Карта источников, статический аудит исходного кода, интеграционная передача и архив ранних планов |
| [research-garden/](research-garden/README.md) | Датированные исследования, источники, школьные материалы и диаграммы |
| [references/](references/README.md) | Локальные снимки исходной документации, HTML-демо/макеты, ролик и питч; не рабочий учительский продукт |
| [SOURCES.md](SOURCES.md) | Происхождение, закрепленные коммиты и правила получения исходного кода |
| [AGENT_WORKFLOW.md](AGENT_WORKFLOW.md) | Три skills, маршрут чтения, карта обновления документов и работа перед push/merge |

Достаточно клонировать этот репозиторий, чтобы узнать продукт, требования, текущий этап и план реализации. Исходники приложений — отдельные upstream-репозитории; ссылки на них закреплены за ревизиями. Для изменения кода потребуются сами исходники и проверка окружения, а не только чтение снимков.

Спецификация описывает будущее поведение. Тесты приложения, реальные вызовы модели, развертывание и школьная апробация не считаются выполненными по наличию документов. Существенные проверенные изменения нужно отражать в CURRENT_STATE и профильных разделах в том же изменении, используя smartnote-doc-sync.
